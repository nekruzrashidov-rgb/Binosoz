# Принятые решения

- Решение в формате `Sitora.sln` (шаблон .NET 10 по умолчанию создаёт `.slnx`, но в ТЗ указан `.sln`).
- Domain подключает только `Microsoft.Extensions.Identity.Stores`, чтобы `AppUser` наследовал `IdentityUser<Guid>`; EF Core и HTTP в Domain нет.
- Роли хранятся в таблицах Identity (`Roles`, `UserRoles`), а не отдельным полем `Role` в `Users`; таблицы Identity переименованы без префикса `AspNet`.
- Добавлено пятое исключение домена `UnauthorizedException` (→ 401) для неверного входа и истёкшей сессии.
- Refresh-токен: 64 случайных байта, в базе только SHA-256 хеш, срок 30 дней, ротация при каждом обновлении; повторное использование старого токена отзывает все сессии пользователя.
- `POST /auth/logout` принимает refresh-токен в теле и не требует access-токена; повторный выход отвечает 204.
- Добавлен `GET /api/v1/auth/me` для проверки токена и получения текущего пользователя.
- Вход блокируется на 15 минут после 5 неудачных попыток (lockout Identity).
- В JWT роли лежат в claim `role`, идентификатор пользователя в `sub` (`MapInboundClaims = false`).
- Миграции применяются автоматически при старте во всех окружениях; роли создаются всегда, пользователи сидера только в Development.
- Если переменная с паролем пользователя сидера не задана, пользователь не создаётся, в лог пишется предупреждение.
- Swagger включён во всех окружениях, кроме Production.
- `Microsoft.EntityFrameworkCore.Design` и фабрика контекста для `dotnet ef` лежат в Infrastructure; `dotnet-ef` установлен локальным инструментом (`dotnet-tools.json`).
- PostgreSQL из docker-compose проброшен на порт 5433, чтобы не конфликтовать с локальным сервером на 5432.
- Тесты используют Testcontainers (`postgres:18`); если Docker недоступен, можно задать `SITORA_TEST_DB` со строкой подключения к своему серверу — тесты создадут и удалят временную базу.
