# Проверка безопасности

Проверено на этапе 6. Отметки: ✅ сделано и покрыто тестом или проверено, ⚠️ сделано с оговоркой, ❌ не сделано (см. «Известные ограничения» в README).

## Требования из ТЗ

| Требование | Статус | Как сделано |
| --- | --- | --- |
| Только HTTPS в продакшене | ✅ | HTTPS завершает Caddy с сертификатом Let's Encrypt. Приложение в Production шлёт HSTS (1 год) и перенаправляет HTTP на HTTPS. Тест `ProductionTests` |
| Лимиты на вход и SMS | ✅ | По IP: вход и refresh — 10 в минуту, SMS — 20 в час, заявки и гостевые брони — 30 в час. На номер — не больше 5 SMS-кодов в час и 5 попыток ввода кода. Ответ 429 на русском. Тесты `RateLimitTests`, `SmsAuthTests` |
| CORS только для своих доменов | ✅ | Список берётся из `Cors:AllowedOrigins`, пустой список выключает CORS. Тест `SecurityTests.Cors_AllowsOnlyConfiguredOrigins` |
| Паспортные данные шифруются, доступ — Manager и Admin | ✅ | AES-256-GCM, ключ в `Encryption__Key`. Данные отдаются только в `GET /customers/{id}` (Manager, Admin), их нет в списке клиентов и в аудите. Тест `CustomerTests` |
| Права на сервере в каждом запросе, чужая сделка — 404 | ✅ | Роли проверяются на контроллерах. Владение сделкой и домом проверяет `DealAccess` во всех сервисах сделки, стройки и чата. Тесты `CabinetAccessTests`, `DocumentTests`, `ChatTests`, `ConstructionTests` |
| Секреты только из переменных окружения | ✅ | В репозитории только заглушки. Проверено поиском по файлам и по всей истории git |
| Serilog, `/health` | ✅ | `/health` проверяет базу и отвечает только `Healthy` или `Unhealthy`, без деталей |
| Окружения Development, Staging, Production | ✅ | Сидер работает только в Development, Swagger выключен в Production. Тесты `StagingTests`, `ProductionTests` |

## Общий чек-лист

| Пункт | Статус | Комментарий |
| --- | --- | --- |
| Пароли | ✅ | Хеш Identity (PBKDF2). Минимум 8 символов, цифра, строчная и заглавная буква. Блокировка на 15 минут после 5 неудачных попыток |
| Перебор и перечисление пользователей | ✅ | Неверная почта и неверный пароль дают одинаковый ответ. `sms/send` отвечает одинаково для любого номера |
| JWT | ✅ | HMAC-SHA256, ключ не короче 32 символов (проверяется при старте), access-токен на 15 минут. Проверяются издатель, аудитория и срок |
| Refresh-токены | ✅ | В базе только хеш. Ротация при каждом обновлении. Повторное использование старого токена отзывает все сессии пользователя |
| Блокировка сотрудника | ⚠️ | `PATCH /users/{id}/status` закрывает вход и сразу отзывает refresh-токены. Выданный access-токен действует до 15 минут |
| SMS-коды | ✅ | 6 цифр, 5 минут, хеш в базе, сравнение за постоянное время. Вне Development заглушка не пишет код в лог |
| Двойная бронь и гонки в платежах | ✅ | Блокировка строк `FOR UPDATE` и частичные уникальные индексы. Тест одновременной брони |
| Загрузка файлов | ✅ | Белый список расширений, проверка первых байтов файла, лимит размера. Путь к файлу строит сервер, выход за папку хранилища запрещён |
| Скачивание файлов | ✅ | Только по подписанным ссылкам на 15 минут (HMAC-SHA256 над типом, Id и сроком; ключ выводится из `Jwt__Key`), их выдают после проверки прав. Подделанная, просроченная или чужого типа ссылка — 404. Документы отдаются как вложение, `Cache-Control: private, no-store`, для всех ответов `X-Content-Type-Options: nosniff`. Тест `FileLinks_RejectForgedExpiredAndWrongKindTokens` |
| Утечка ссылки на файл | ⚠️ | Ссылка работает у любого, кто её получил, но только 15 минут. Токен в строке запроса: Serilog его не пишет, `Referrer-Policy: no-referrer` не даёт ему уйти на чужие сайты; в логах Caddy URI с токеном есть |
| Защитные заголовки | ✅ | `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Content-Security-Policy: default-src 'none'` (кроме Swagger). Заголовка `Server` нет |
| Ошибки | ✅ | Наружу уходит Problem Details без стека и типов исключений, подробности — только в лог. Тест `Errors_DoNotLeakInternals` |
| SQL-инъекции | ✅ | Только EF Core и параметризованный `FromSql` |
| Аудит | ✅ | Статусы, цены, платежи, сторно, документы, курс, пользователи. Записывается в той же транзакции, что и изменение |
| Заголовки прокси | ✅ | `X-Forwarded-*` принимаются, только если включено `ForwardedHeaders__Enabled`, и только от одного прокси. В prod-compose API не открыт наружу, доступ только через Caddy |
| `AllowedHosts` | ✅ | В prod-compose равен домену API |
| База данных | ✅ | Порт наружу не открыт, пароль из `.env`, данные на томе docker |
| Контейнер | ✅ | Многоэтапная сборка, процесс работает не от root |
| Swagger и дашборды | ✅ | Swagger выключен в Production. Дашборд Hangfire не подключён |
| Токен в строке запроса для SignalR | ⚠️ | Нужен браузеру для WebSocket и принимается только на `/hubs`. Serilog пишет путь без строки запроса. Логи Caddy содержат URI, поэтому при отладке не публикуйте их |
| Уязвимые пакеты | ✅ | `dotnet list package --vulnerable --include-transitive` — уязвимостей нет. `Newtonsoft.Json` (зависимость Hangfire) закреплён на 13.0.4 |
| Персональные данные в логах | ⚠️ | Заглушка Telegram пишет в лог текст уведомления с именем и телефоном клиента. При подключении настоящего Telegram стоит убрать текст из лога |
| Резервные копии | ⚠️ | `scripts/backup.sh` и `restore.sh` готовы, но не проверялись на сервере. Копии нужно выносить с сервера |
| Сброс и смена пароля | ❌ | Не реализованы. Пароль сотруднику задаёт администратор при создании |

## Перед запуском в продакшен

1. Подключить настоящего SMS-провайдера вместо заглушки, иначе покупатели не войдут.
2. Пройти docs/DEPLOY.md на сервере, включая раздел «Проверка после деплоя».
3. Проверить восстановление из бэкапа.
4. Сохранить `ENCRYPTION_KEY` и `.env` вне сервера.
5. Проверить, подходит ли застройщику Community-лицензия QuestPDF.
