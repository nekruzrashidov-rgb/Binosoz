Регистрация подтверждается кодом из письма; до подтверждения войти нельзя (и об этом говорится только тому, кто ввёл верный PIN). Тесты `CustomerPinTests` |
| «Забыли код?» | ✅ | Запрос кода отвечает одинаково для любой почты, письмо — только покупателю. Ограничения: вопрос ≤ 500 символов, история — 10 последних реплик (по 1500 символов), ответ ≤ 400 токенов; лимит `AiPublic` на IP — 6 в минуту и 40 в сутки (оба окна сразу, вошедший покупатель считается по IP, как гость); общий суточный лимит организации `Claude:PublicDailyLimit` (300). ## Перед запуском в продакшен

1. Подключить настоящего SMS-провайдера вместо заглушки, иначе покупатели не войдут.
2. Пройти docs/DEPLOY.md на сервере, включая раздел «Проверка после деплоя».
3. Проверить восстановление из бэкапа.
4. Сохранить `ENCRYPTION_KEY` и `.env` вне сервера.
5. Проверить, подходит ли застройщику Community-лицензия QuestPDF.

## Ротация секретов

Когда менять: сразу при подозрении на утечку (ноутбук, логи, `.env` в переписке, уволился человек с доступом к серверу), плановая — раз в год. Все секреты лежат в `/opt/sitora/.env` на сервере (на Render — в Environment). После каждой замены — `docker compose -f docker-compose.prod.yml up -d webapi` и проверка `curl https://<API_DOMAIN>/health/ready`.

Новые значения:

```bash
openssl rand -base64 48   # JWT_KEY (не короче 32 байт)
openssl rand -base64 32   # ENCRYPTION_KEY (ровно 32 байта)
openssl rand -base64 24   # пароли
```

| Секрет | Как заменить | Последствия |
|---|---|---|
| `JWT_KEY` | Новое значение в `.env`, перезапуск API | Все access-токены (живут 15 минут) перестают приниматься; фронтенд сам получает новые через `/auth/refresh` — refresh-токены от ключа не зависят. Пользователи не выходят |
| Refresh-токены (все сессии) | `docker compose -f docker-compose.prod.yml exec db psql -U sitora -d sitora -c 'UPDATE "RefreshTokens" SET "RevokedAt" = now() WHERE "RevokedAt" IS NULL;'` вместе со сменой `JWT_KEY` | Все пользователи входят заново. Нужно при утечке базы или `JWT_KEY` |
| `POSTGRES_PASSWORD` | 1) `docker compose -f docker-compose.prod.yml exec db psql -U sitora -c "ALTER USER sitora PASSWORD 'новый'"`; 2) то же значение в `.env`; 3) перезапуск API | Переменная `POSTGRES_PASSWORD` действует только при первом создании базы, поэтому сначала `ALTER USER`, потом `.env`. `backend/scripts/backup.sh` работает через `exec` внутри контейнера базы и пароля не требует |
| `ENCRYPTION_KEY` | **Сейчас не меняется.** Паспортные данные зашифрованы одним ключом (AES-256-GCM, формат `v1:`), идентификатора ключа и перешифровки нет: после замены старые записи не расшифруются | Нужна доработка: формат `v2:<id ключа>:…`, список ключей (новый для записи, старые для чтения) и задача перешифровки. До неё — хранить ключ отдельно от бэкапов и не менять |
| `Telegram__WebhookSecret` | Новый секрет в окружение API, перезапуск, затем снова `setWebhook` с новым адресом и `secret_token` (`docs/DEPLOY.md`) | Пока webhook не перерегистрирован, бот не отвечает на `/start` |
| `Telegram__Gateway__Token` | gateway.telegram.org → API → новый токен, старый отозвать; новый — в окружение API | Без токена вход по телефону выключен (`telegram: false`) |
| `Telegram__BotToken` | В @BotFather: `/revoke` → новый токен в окружение API, перезапуск. В `docker-compose.prod.yml` — `TELEGRAM_BOT_TOKEN` в `.env` | Чаты, уже привязанные к боту, остаются |
| `RESEND_API_KEY`, `SMTP_PASSWORD` | Новый ключ в кабинете Resend (или пароль у почтового провайдера) → `.env` → перезапуск; старый ключ удалить в кабинете | Письма с кодами не уходят только во время перезапуска |
| `CLAUDE_API_KEY` | Новый ключ в console.anthropic.com → `.env` → перезапуск; старый отозвать | — |
| `ADMIN_PASSWORD`, `SEED_*_PASSWORD`, `BOOTSTRAP_ADMIN_PASSWORD` | Сменить пароль в самом приложении («Забыли пароль?» или профиль); значения в `.env` нужны только сидеру при первом запуске | — |

Где ещё могут лежать секреты: GitHub Actions Secrets (деплой по SSH), Render Environment, `dotnet user-secrets` на машинах разработчиков. После ротации обновите их тоже и проверьте, что `.env` не попал в git: `git log --all -- .env` должен быть пустым.
